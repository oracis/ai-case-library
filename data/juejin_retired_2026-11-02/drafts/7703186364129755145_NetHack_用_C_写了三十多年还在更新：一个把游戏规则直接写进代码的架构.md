# NetHack 用 C 写了三十多年还在更新：一个把游戏规则直接写进代码的架构

> 摘要：一个 1987 年开始的项目，到今天仍有人提交 PR。没有框架、没有引擎、没有资源文件——所有规则都是 C 代码，所有「内容」都是宏和表格。

一个 1987 年开始的项目，到今天仍有人提交 PR。没有框架、没有引擎、没有资源文件——所有规则都是 C 代码，所有「内容」都是宏和表格。

读它的源码，能看到一种跟现代游戏开发完全相反的架构取向：**不为扩展性做抽象，为确定性做约束**。这套取向解释了一个问题：为什么 Roguelike 能靠纯代码堆出几十年的内容深度。

## 一、代码的组织方式

- 语言：C（C99 风格，但保留了极多老式写法）
- 目录：`src/`（逻辑）、`include/`（头文件与全局声明）、`dat/`（描述文本）、`sys/`（平台适配）
- 无第三方引擎依赖，只用 libc 和 curses/终端
- 构建：传统 Makefile 分支（`sys/unix`、`sys/winnt`）

理解它的钥匙在 `include/`：`hack.h` 几乎把所有东西都声明了，`extern.h` 定义跨模块类型与错误处理。这是典型的「单一全局头 + 按功能切源文件」的老派 C 架构。

## 二、为什么规则写死在代码里反而是对的

现代做法是把怪物、物品、技能做成配置文件。NetHack 没有——怪物行为在 `monst.c` 里是一张巨大的结构体数组：

```c
struct permonst monstra[NUM_MONS] = {
    { "giant ant", 'a', 2, 0, 0, 0, 3, 7, 0, 0, ... },
    { "kobold",    'k', 0, 0, 0, 0, 2, 2, 0, 0, ... },
    /* 每个字段是位标志或小整数 */
};
```

每行字段是定长的，位置敏感——加字段要改全表，这是它「难改」的根源。

但换来的是：**确定性的数值布局，让存档二进制、能量消耗、命中判定全部可以逐字节推演**。Roguelike 玩家社区会研究「第 15 回合的怪物生成是否可预测」，这种深度依赖稳定的内部表示。

这不是说配置化不好，而是：**如果你的产品核心价值是「可推演的确定性」，那么把规则做成数据反而会引入不确定**。

## 三、宏代替了抽象层

NetHack 里最典型的模式是「宏即语法糖即行为」：

```c
#define rn2(x)  (int)(rn2_on_display_rng ? ... )
/* 随机数统一入口，便于回放与调试 */

#define cansee(x,y) (isok(x,y) && ...)
```

它用宏把「视野判断」「随机数」「消息输出」这些横切关注点统一收口。好处是所有调用点行为一致，坏处是调试栈里全是宏展开，断点很难打。

对现代工程的映射：这就是没有 AOP 和依赖注入的时代，用预处理做横切。今天的等价物是中间件、装饰器、日志切面。

## 四、随机数与可复现性

Roguelike 的可复现是个硬需求——玩家会分享「种子」，社区会复现同一个地牢。

NetHack 的做法：全局 RNG 状态集中管理，所有随机都过 `rn2()`/`rnd()` 入口，不允许业务代码直接调 `rand()`。这是**把随机收口成单一服务**的经典做法。

工程上这条极其通用：只要你的系统需要「可重放」，就必须让所有不确定性来自单一可注入的源（时间、随机、ID 生成）。

## 五、终端渲染与「无图形引擎」

它没有渲染引擎，直接用 curses 画字符：

- 地图 = 80×21 的字符网格
- 每个格子映射一个 glyph（`'a'` 蚂蚁、`'d'` 狗）
- 颜色靠终端的 16 色属性位

这种「渲染 = 字符串拼接」的方式今天看起来原始，但它带来一个真实优势：**任何有终端的地方都能跑**，包括 SSH 到一台路由器上。

对做工具类产品的启发：输出层越薄，可移植性越强。

## 六、读代码的入口

1. `include/hack.h` —— 全局数据结构，先扫一遍再读逻辑
2. `src/allmain.c` —— 主循环，看一个回合由哪些阶段组成
3. `src/monst.c` —— 怪物表，理解数据布局
4. `src/dothrow.c` / `src/dokick.c` —— 单个动作的完整实现，适合作为「一个功能怎么落地」的样例

## 七、编译与门槛

- 现代编译器会报大量警告（老式 C 写法），`-Wno-*` 免不了
- Windows 下需要 MinGW 或 MSVC 工程，官方 `sys/winnt` 目录里有配置
- 无单元测试，改动靠「跑一遍看有没有崩」——这是它最大的工程债

## 八、能搬走什么

- **横切关注点必须收口**（随机数、视图、消息），否则行为无法统一
- **确定性比灵活性值钱**，取决于你的产品是不是「可推演」类型
- **没有测试的成熟项目，改动的风险随时间线性上升**——反面教材也值得看
- **输出层越薄，产品触达面越广**
