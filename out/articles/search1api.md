# Search1API：不赌哪个 AI 会赢，只卖它们都需要的那次联网

> 「把 TrustMRR 上的 $49,299 当作年营收/ARR 使用（并据此得出约 1x 的挂牌倍数）」

> 我去核了一遍：$49,299 是 All-time 累计收入（lifetime），当前 MRR 为 $1,408、最近 30 天验证收入 $1,308


## 它是干什么的

搜索类 API 服务


## 钱从哪来

把搜索、爬取、摄取做成一次 API 调用，按调用量/套餐计费；通过 API、MCP、CLI 或 skills 接入任意 agent。当前 MRR $1,408、近 30 天验证收入 $1,308、累计 $49,299；标的叫价 $50,000。


## 它到底做到多大

| 维度 | 内容 |
| --- | --- |
| 官方口径 | 收入 $1.3K / 售价 $50K / 倍数 3.2x（TrustMRR 市场挂牌） |

**还有一条被抄错的流传的说法**：用「收入 $1.3K」与售价 $50K 直接相除来解释 3.2x 倍数

**实际情况**：3.2x 来自年化口径 $50,000 ÷（$1,308×12≈$15,700）；若用单月 $1.3K 直接相除约为 38x，两者不是一回事


## 它为什么能成

- 联网是 agent 的刚需，而它被拆成搜索 / 爬取 / 摄取三个可单独计费的动作，天然适合按量收费。
- API + MCP + CLI + skills 四个入口把不同习惯的开发者一网打尽，接入摩擦几乎为零。
- 站在基础设施位而不是应用位，需求随 agent 数量增长，不需要押注某一个上层产品。
- 无状态 + 按量计费意味着一个人就能运维，$1,408 的 MRR 对单人项目是可持续的规模。

## 能搬走的部分

- 做淘金热里的管道：不猜哪个 agent 会赢，卖它们都需要的那一层。
- 多入口接入的成本很低，但对接率差别很大——MCP 尤其值得先做，它现在是 agent 的默认插口。
- 按调用量收费要先算清上游成本（搜索源 API 本身要钱），否则收入只是转售差价，规模越大毛利越薄。
- 基础设施类项目的估值看调用量曲线和留存，不看用户数——$50,000 叫价对应的是这条曲线的斜率。
- 累计收入 $49,299 是 lifetime 不是 ARR：读挂牌数据先分清口径，否则倍数会算错一整个量级。

国内 agent 生态同样缺一层「联网」，需求真实且正在增长；收款无障碍，获客靠开发者社区这条路在国内也成立。两个要改的地方：搜索源要换成国内可用的（或合规抓取），而「抓取什么、能不能抓取」的合规边界比美国更模糊 —— 这是唯一需要谨慎的维度。竞争已经存在（各家大模型的搜索 API、博查一类），但 MCP 这一层还没人占死。

## 我的判断

它做的是 agent 时代的管道生意：不赌哪个 agent 赢，只卖它们都需要的那一次「联网」——按调用量收费，一个人就能运维。

**结论**：能做，但别在国内卖（综合 64.0 分）
