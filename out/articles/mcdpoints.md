# 用麦当劳官方接口查了一下，我的积分正在悄悄过期

麦当劳的积分会过期，这件事官方从来不提醒你。等你某天想起来，它们早已经归零了。

前阵子麦当劳中国开放了官方 MCP 接口，一共 30 个工具。我翻的时候注意到其中一个叫 `query-my-account` 的接口，返回里有个字段是「即将过期积分」——这是整个工具集里唯一带时间压力的数据。

于是我拿自己的账号跑了一次。结果比想象中难看。

## 我的真实账户数据

| 维度 | 数值 |
| --- | --- |
| 可用积分 | 63 |
| 本月将过期 | 39 |
| 累计积分 | 4,742 |
| **已过期作废** | **2,938** |

两千九百多分，已经白白没了。这个数字比「即将过期」扎心得多——前者已经损失，后者还能抢救。

## 做了个东西：麦麦积分清仓官

逻辑很短，三步：

1. 读 `query-my-account`，取出即将过期和已过期的积分
2. 枚举麦麦商城的可兑换商品，算出过期前最划算能换什么
3. 一键下单换掉，最后导出一张可以发朋友圈的「积分体检卡」

第二步有个坑：商城接口不传类目参数时，返回里会混进大量积分为 0 的生日派对商品，得按 `1>4`（商品券）、`2`（实物）、`2>8`（周边）、`2>9`（礼品卡）四个类目分别拉取再合并去重。

## 实现上几个值得一提的点

**结构化数据不在你以为的地方。** MCP 响应的 `content[].text` 字段是一段给大模型看的 Markdown 说明文档，真正的业务数据藏在 `structuredContent.data` 里。第一版代码对着 `content` 做 JSON 解析，结果把所有积分读成了 0，我一度以为是自己账号没积分。官方文档里完全没提这回事。

**营养数据是 TOON 格式，不是 JSON。** 官方为了省 token，把 160 道餐品的营养表压成一种叫 TOON 的字符串格式：`[160]{productName,energyKj,energyKcal,...}:` 后面每行一条、逗号分隔。按 JSON 数组去找行，一条都找不到。

**点餐类接口必须带门店参数。** 但不用你填地址——`delivery-query-addresses` 无需入参就能拿到地址列表，顺着地址查门店、查菜单、查套餐详情，整条链路可以全自动跑完。

**零第三方依赖。** 单文件 Python + 单文件 HTML，两个文件就能跑起来。Python 标准库自带 HTTP 客户端，MCP 的 JSON 和 SSE 两种响应格式都做了解析。没申请 Token 也能直接看演示效果。

## 顺手还做了另一个

麦当劳套餐里那些「可替换选项」（可乐换咖啡、小食换鸡翅），官方菜单上只让你一个一个换，从没告诉你全排列是什么样。

我用 `query-meal-detail` 把可替换项做笛卡尔积枚举，剔除原版搭配，再套上官方营养接口的热量数据，一次组合出 **2,216 种**隐藏搭配，还给每种起了名字：轻断食暗号、穷鬼暗号、提神暗号……
