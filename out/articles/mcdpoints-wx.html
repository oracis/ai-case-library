用麦当劳官方接口查了一下，我的积分正在悄悄过期

麦当劳的积分会过期，这件事官方从来不提醒你。等你某天想起来，它们早已经归零了。

前阵子麦当劳中国开放了官方 MCP 接口，一共 30 个工具。我翻的时候注意到其中一个叫 query-my-account 的接口，返回里有个字段是「即将过期积分」——这是整个工具集里唯一带时间压力的数据。

于是我拿自己的账号跑了一次。结果比想象中难看。

我的真实账户数据

可用积分　　　　63

本月将过期　　　39

累计积分　　　　4,742

已过期作废　　　2,938

两千九百多分，已经白白没了。这个数字比「即将过期」扎心得多——前者已经损失，后者还能抢救。

做了个东西：麦麦积分清仓官

逻辑很短，三步：

1. 读 query-my-account，取出即将过期和已过期的积分；
2. 枚举麦麦商城里所有能兑的商品，算出「在过期前用掉最多积分」的那一件；
3. 一键兑换，并导出一张可以发出去的积分体检卡。

零第三方依赖：一个 Python 文件自带 MCP 客户端，一个 HTML 文件是界面。没有 Token 也能跑演示模式。

官方文档没写的三个坑

一、真正的结构化数据不在 content 里。第一版我把返回当成 JSON 解析，积分全读成 0，一度以为是自己账号没分。实际数据在 structuredContent.data 里，而 content[].text 是给大模型看的 Markdown 说明文档。文档里一个字没提。

二、营养接口返回的是 TOON，不是 JSON。形如 [160]{字段列表}: 加每行一条逗号分隔。直接按数组找行会得到 0 条。自己写了个解析器才拿到 160 道餐品的热量。顺带说清一件事：energyKcal 是千卡，energyKj 是千焦，别取错。

三、点餐接口必须带门店参数。不带就返回 400 缺少参数，但文档没写缺的是什么。我打通了一条全自动链路，不用你填地址：先查地址列表，再查可配送门店，再取菜单，最后取套餐详情。

顺手做了第二个：麦麦暗号厨房

套餐里的每个选项其实都能换——可乐换咖啡、薯条换玉米杯。我把所有可替换项做笛卡尔积枚举，剔除原版搭配，算出真实价格和热量，再按规则打上暗号标签。实测一次组合出 2216 种菜单上不存在的搭配，比如「大杯鲜萃咖啡 + 不加价 + 237 kcal」。

为什么写这两个

因为积分过期这件事，没有人在提醒。官方 App 不会弹窗，也不会发消息。它只是安静地归零。

两个项目都在 GitHub 开源，零依赖，克隆下来就能跑：

麦麦积分清仓官　github.com/oracis/mcd-points-liquidator

麦麦暗号厨房　　github.com/oracis/mcd-secret-kitchen
