# 一份 PDF 的交付成本在哪：内容资产的存储、签名链接与团队授权

Refactoring UI 是 Adam Wathan 与 Steve Schoger 写给开发者的界面设计资料：50 章、200 多页 PDF，讲的是「不靠美术直觉也能做出像样界面」的具体手法，另外还附了 screencasts 与一套组件资源。它是纯静态内容，没有账号体系，也没有常驻服务。

换个角度，从资源与弹性的账本看这个形态：一个全年只有「收款、发文件」两个动作的系统，它的负载几乎全部集中在发布日那几小时，其余时间接近零。

这里不谈定价策略，只谈负载形状会怎么反过来约束架构。

## 一、负载长什么样

把它的访问拆成三类，形状完全不同：

- **发布瞬时峰**。新品上线当天，下载请求从零跳到几千并发，然后一两周内衰减到每天几十次。峰值与常态差两三个数量级。
- **长尾读取**。老买家的下载链接可能在任何一天被点开，包括四年后。这类请求量小但绝不能失败，因为一次 404 就是一个退款工单。
- **后台写入**。订单、发货记录、链接映射，写入量极低，但要求强一致——丢一条就是「钱收了没给货」。

三类负载混在一个服务里做容量规划是最常见的错误：为峰值准备常驻实例，长尾时间全是浪费；按常态配置，发布日必然打穿。

## 二、资源与成本的取舍

按「峰值与常态差两个数量级」这个前提，合理的切法是**把峰值能力交给对象存储与 CDN，把一致性要求交给数据库**：

1. **文件本体不经过应用服务器**。PDF、视频课程、组件包全部放对象存储，应用只负责签发下载凭证。这样峰值压力落在存储与 CDN 上，它们本来就是按请求弹性计价的，不需要提前备机器。
2. **下载链接用短期签名，不用固定地址**。签名链接可以带过期时间与下载次数上限，既防外泄又天然支持「重新生成」——老买家链接失效时不用改代码，重新签一次即可。固定 URL 一旦流到公开渠道就是永久盗版源，且无法回收。
3. **CDN 只对高频对象开**。200 多页 PDF 与视频是热点，组件包更新频繁、单次体积大但访问稀疏，后者走源站直连更省。全部塞进 CDN 会把缓存成本抬上去，收益却只在少数对象上。
4. **支付回调是唯一的发货凭据**。前端跳转到成功页不算数——用户关页面、网络中断都会让前端状态失真。回调还必须幂等，支付平台会重发，重复处理就是重复发货。
5. **订单到文件的映射必须持久化且可查询**。用户两年后说「链接打不开了」，能不能一条查询找回，取决于当初有没有存这条映射。这是整个系统里最便宜也最容易被省掉的一张表。

可观测性上只有两个指标真正需要盯：**付款成功到发货完成的时延分布**，和**下载失败率**。前者异常说明回调链路堵了，后者异常说明签名或存储权限出了问题。这两条比 CPU、内存更能反映这个系统的健康。

多租户在这里的含义不是「多个客户隔离数据」，而是**同一份文件要区分授权口径**：个人买家、团队采购、教育授权，看到的是同一个 PDF，但允许的席位和分发范围不同。把授权做成独立一层（订单 → 授权记录 → 签发凭证），而不是塞进文件名或水印里，后期改授权规则才不用重新发文件。

## 三、公开数字的时点

以下都是创始人公开披露，只作为形态参照，不代表可持续增速：

- 截至 2022 年 9 月，累计营收超过 250 万美元（创始人在 Indie Hackers 的 AMA 自述）；
- 2020 年全年营收约 60 万美元，即出版约两年后的长尾水平；
- 首周 61,392 美元；
- 后续组件库上线首日 40 万美元。

> 数据时点 ｜ 2022-09（创始人 AMA 自述）｜ 口径：买断制累计营收，无 MRR/ARR 概念

这组数字里最值得注意的不是绝对值，而是**首周与长尾的比例**：首周就吃掉了相当一部分总量，说明这类产品的收入曲线极度前置，后面几年是缓慢的长尾。对容量规划的直接含义是——按发布日设计弹性，按长尾设计成本，不能反过来。

## 四、判断与适用边界

这套形态能成立，依赖三个前提：

- **内容基本稳定**。买断隐含「终身可用」，如果内容需要频繁更新（比如工具类教程跟着版本走），维护成本会持续上升而没有持续收入对冲，这时买断制不成立。
- **受众已经存在**。它的转化不依赖投放，靠的是作者长期写博客、做开源（后来的 Tailwind CSS）积累的信任。没有受众池的同类产品，发布日的峰值根本不会出现，弹性设计也就失去意义。
- **盗版成本高于售价**。数字内容必然会被分享，技术手段只能提高成本不能阻止。合理的做法是把价格放在「懒得找盗版」的区间，并把价值放在文件之外——更新、示例代码、问答——而不是做 DRM。DRM 挡不住真正的分发者，只会伤害正常买家的下载体验。

反过来，如果产品是订阅制、内容持续更新、或者买家以团队为主，那么结论会变：授权与席位要单独计价，交付链路要支持撤销与转移，可观测性也要从「下载失败率」扩展到「席位活跃度」。

结论：负载形状决定成本结构，成本结构再决定哪些设计能长期扛住。Refactoring UI 的数字是快照，引用带时点。
