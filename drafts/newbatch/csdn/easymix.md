# 一键出歌：法语说唱自动混音与母带工程

把一段人声加一条伴奏变成能直接上架的成品，传统流程要在宿主软件里逐轨调整、逐项挂效果、再按发行渠道分别导出。easyMix 把这条链路收成一次上传：交主唱、和声与伴奏分轨，选一个风格预设，几秒后拿到成品。公开资料没有披露内部实现，下面只写看得见的输入输出契约，不推测模型结构或效果器细节。

## 分轨输入与风格预设组成的入口契约

用户侧交的不是单个混好的文件，而是主唱、和声、伴奏三条分离的轨道，外加一句文字风格描述（例如 drill、旋律说唱）。这个约定把分轨准备留在用户侧，服务端拿到的是可以分别处理的素材。风格描述与预设充当参数入口：用户不必理解均衡、压缩这类中间量，只需给出想要的结果描述。

从工程角度看，这是把原本分散在宿主软件工程文件里的一组参数，压缩成「上传 + 选风格」两个动作，交付物也从工程文件变成可直接上架的音频文件。产品面向法语区说唱歌手与独立音乐人，界面与文案统一用法语，切口很窄，但输入输出边界因此格外明确。

## 混音与母带合并成一次提交

产品说明里列出的处理项包括自动调音、均衡、混响，几秒内得到成品；另一项 AI mastering 把已混好的歌压成适配不同发行渠道的版本。值得注意的是这两段被打包在同一次上传里：官网说明 mastering 含在每份方案内，没有单独再传一次的入口。

对使用者来说，少一次提交意味着少一次状态等待；对交付面来说，混音与母带不再是两个各自可能失败的步骤，而是一个原子结果的两种处理阶段。这里能确认的只有「一次上传、一份成品」；内部是否真的共用一条处理链，公开资料没有说明，不做推断。

## 面向多个分发渠道的输出版本

mastering 的产出不是单一文件，而是适配 Spotify、Apple Music、TikTok 等渠道的版本。同一首歌在不同渠道的响度与格式要求并不一致，把这些差异放在服务端一次性生成，用户就不必自己维护一套导出配置。这也是「成品」二字的实际含义：拿到的是按渠道准备好的文件，不是还需要二次处理的中期文件。

产品把「专业」这件事压缩成一个按钮。公开的客户评价集中在「以前在家录不出能听的版本」与「以前要花大钱买插件还搞不定」，说明用户感知到的是结果而不是中间链路。取舍同样清楚：放弃逐项可调，换取一次上传即出结果的确定性。

## 规模数据的取数链路与时点

这类产品最容易被含糊转述的是规模数字。公开核验快照注明数据由支付网关 API 直读，而非后台自报：近 30 天已验证流水 7,926 美元、累计 37,012 美元。

数据时点 ｜ 截至 2026-10-05（抓取日快照，支付侧同步时间 2026-10-04）｜口径：近 30 天为滚动 30 天已验证流水，含一次性与用量收入，不是月经常性收入；累计为历史合计，不可年化。

技术上这意味着取数链路是「支付商 API → 只读快照」，好处是可复核，代价是快照会过期。任何转述都必须带上时点：把滚动 30 天流水当月经常性收入引用，或把累计数当当期数，都是口径错误。核验快照里没有客户数这一指标，所以本文不写用户规模，也不引用未经复核的环比。

一句话总结：把分轨输入、风格预设与多平台输出版本固定成一条处理链，价值不在某一项效果，而在交付面只剩一次上传。

出处：支付网关核验快照与产品官网公开说明（2026-10-05 抓取）。
