# 4×4 网格怎么写出「合并」手感：读开源 2048 的代码结构

2048 大概是"规则一句话能讲完、实现起来却处处有细节"的典型：4×4 棋盘，滑动让相同数字合并翻倍，凑出 2048 就算通关。它 2014 年由 Gabriele Cirulli 写成网页版并开源，之后被移植到几乎所有平台。

本文读的是原作者那个仓库（gabrielecirulli/2048，MIT 许可，JavaScript，一万三千多 star），讲它的代码分层和几个容易写错的地方。仓库在 GitHub 上，浏览器直接打开 index.html 就能跑，不需要构建。

## 玩法与仓库形态

规则很薄：每次滑动，整行或整列的方块朝同一方向移动，相同数字相撞就合并成两倍；每滑动一次，随机空格里补一个 2 或 4。棋盘填满且四个方向都无法合并时结束。

仓库里只有代码，没有额外素材包：界面用的是纯 CSS 色块和系统字体，所以"下载即玩"这件事在这里是真的成立——不需要自备图片和音效。

## 一个页面跑起来需要几层

拆开看，它大致分了四层职责：

- **输入层**：监听键盘方向键和触摸滑动，把"往哪个方向滑"转成一个方向常量。
- **状态层**：维护 4×4 的格子数据、当前得分、是否结束。
- **渲染层**：把状态映射成 DOM 节点，负责方块的位置、颜色和出现/合并动画。
- **持久层**：把当前局面和最高分写进浏览器的 localStorage。

分层带来的好处很实际：换一套皮肤只动渲染层，加"撤销"只动状态层，接手柄只动输入层。

## 合并算法：遍历顺序决定手感

这是整个游戏唯一有坑的地方。

直觉写法是"两两比较，相同就合并"，然后立刻就会遇到经典问题：一行是 `2 2 2 2`，向左滑，正确结果是 `4 4`；但如果你从左往右边扫边合并，很可能得到 `4 2 2` 甚至 `8 2`（连续合并了两次）。

约束有两条：

1. **一次滑动中，每个方块最多参与一次合并**。
2. **遍历要从滑动方向的"最远端"开始**，否则前面的合并会挡住后面的移动。

以向左滑为例：对每一行，从第 0 列开始向右扫；每个方块只往左看一格，如果那一格是空的就移过去继续看，如果是相同数字且那个方块本轮还没合并过，就合并并把两者都标记为已合并。

```text
for each row (向左滑):
    for col from 0 to 3:
        t = row[col]
        if t is empty: continue
        c = col
        while c > 0 and row[c-1] is empty:
            move t to c-1; c = c - 1
        if c > 0 and row[c-1].value == t.value and not row[c-1].merged:
            row[c-1].value *= 2
            row[c-1].merged = true      # 本轮不再参与合并
            remove t
            score += row[c-1].value
        else:
            place t at c
```

那个 `merged` 标记就是全部秘密。`2 2 2 2` 向左：第一个 2 撞第二个 2 合成 4 并标记，第三个 2 想撞这个 4 时发现它已标记，于是停在 4 右边变成 `4 2 2`；第四个 2 再和第三个 2 合成 4，最终 `4 4`。

四个方向的代码没必要写四份：把棋盘旋转到"向左"的等价形态处理完，再转回来就行。这也是这类网格游戏常见的手写优化。

## 状态和 DOM 别混在一起

很多教程版 2048 会把数据和 DOM 节点绑在一起（每个 tile 既是数据结构又是 div）。这样写短，但加动画时会很痛苦——你要在"数据变了"和"DOM 还没渲染完"之间做时间同步。

更稳的做法是让状态层输出一份"变动清单"：哪些格子移动了（从哪到哪）、哪些是新生成的、哪些合并了。渲染层拿清单去做 CSS transform 动画，动画结束后再统一重排 DOM。这样动画时长和游戏逻辑解耦，用户狂按方向键也不会把状态搞乱。

顺带一个体验细节：滑动无效时（没有任何方块移动或合并）不应该生成新方块，也不应该加分。判断标准是"这一步有没有产生位移或合并"，而不是"用户有没有按键"。

## 存档只存三样东西

localStorage 里其实不需要存整个 DOM 或动画状态，存三样就够：4×4 的数字矩阵、当前得分、历史最高分。重进页面时按矩阵重建 DOM，把最高分读出来显示。

要注意的是版本兼容：如果之后改了棋盘尺寸或存档结构，读旧数据时要做一次字段校验，否则用户会因为一条格式不符的旧存档而白屏。
