# 用 API 实现电话邮箱 IP 实时校验与风控

## 以接口形式封装高频脏活
一个 API 解决「这个电话/邮箱/IP 是不是真的、值不值得联系」：实时校验号码有效性、邮箱可达性、IP 风控画像，按调用量计费。卖的不是数据列表，是「调用那一刻的判定」。

公开口径：MRR 244,029 美元；累计收入 4,985,134 美元（Stripe 直连验证）。

数据时点 ｜ 截至 2026-09-20（抓取日快照）｜口径：MRR

## 按调用量计费匹配业务增长
按 API 调用量计量结算。校验是客户业务链路里的一环，用量随业务规模自然增长 —— 不靠加席位，靠用量自己往上走。

## 用准确率构筑竞争壁垒
- 先找一个「所有业务都要处理、但所有人都不想自己做」的脏活（号码校验、邮箱清洗、风控评分），把它做成一个调用接口而不是一个后台系统
- 按调用量而不是按席位计量：客户的用量随业务自然增长，不用靠涨价
- 把校验结果的质量本身做成壁垒 —— 准确率是一分一分调出来的，这比功能多更难被抄
- 先在开发者社区（而不是营销渠道）建立信任：这类工具的采购决策人就是写代码的人

## 低迁移成本实现高客户黏性
- 选了一个「不性感但刚需」的品类：反欺诈、去无效线索、注册防刷，是每家有表单的业务都要花的钱，但没人愿意为它做产品 —— 于是竞争极小、客户极黏
- 一次接入、长期按量调用：校验发生在客户的业务代码里，换供应商要改代码重测，迁移成本天然高于普通 SaaS，所以流失率极低
- 数字由支付网关直读、不靠创始人自报：这是这个库里可信度最高的一档证据

一句话总结：最值得抄的不是它的技术，是它的选品：主动挑一个「无聊到没人愿意做、但每家公司都得付钱」的环节，然后用按量计费把客户的增长变成自己的增长。
