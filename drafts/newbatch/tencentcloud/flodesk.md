# 「无限发送」的邮件平台，实际在做的是送达率工程

Flodesk 是一个面向小企业和个人创作者的邮件营销平台。它的差异点在设计：模板好看、可自定义字体与配色、编辑器像设计工具而不是表单。2026 年 6 月它推出了 AI 设计应用 Flodesk Studio。

它的定价方式更值得注意：所有付费档 **19 美元起步，且不限发送量**。这句话在营销上很有力，在工程上则意味着一个必须回答的问题——**用户发得越多，你的成本与风险越大，价格却不变，靠什么撑住**。

据官方 2026 年 1 月新闻稿与官网双源披露，平台年化收入超过 3600 万美元，10 万以上小企业客户；2025 年用户经平台发送 130 亿封邮件、新增 3.14 亿订阅者；2019 年创立至今零外部融资，上线第二周即盈利。创始团队包括 Rebecca Shostak（2026 年起任 CEO）、Martha Bitar、Trong Dong，2018 年被 YC 拒绝后自筹起步。

## 一、「无限发送」不是慷慨，是把矛盾转移到了送达率

按发送量计价的平台（多数同类产品如此），商业模型很直接：发得多就付得多，成本与收入同向。Flodesk 反过来做，等于自己承担了「重度用户」的全部边际成本。

这个选择能成立，只有一个前提：**绝大多数用户的实际发送量远低于他们的心理预期**。小企业的邮件列表通常在几百到几千人，一个月发四次，量级很小；真正会「无限发」的是少数，而少数重度用户产生的成本，可以被大量轻度用户的固定订阅费覆盖。这是典型的用量池模型。

但它带来一个直接后果：**没有价格杠杆可以抑制滥用**。按量计价的平台可以用账单劝退乱发的人，无限量平台不能。所以它必须用另一套机制守住底线——**发送质量**。

具体说，如果平台允许任何人无限制地往任意列表发信，很快会出现两类用户：买来的名单、以及内容接近垃圾邮件的东西。这两类用户会让平台的发信 IP 声誉下降，而声誉一旦下降，**所有用户的邮件都会进垃圾箱**。对邮件平台来说这是生存级风险，比多花点服务器钱严重得多。

所以「无限发送」的真实含义是：**平台把风控从计费环节搬到了发送环节**，用准入、限速、质量监控代替账单。

## 二、一封营销邮件要过四道门

想让邮件进收件箱而不是垃圾箱，需要同时过四关。这四关是邮件工程的基本盘：

**第一关：身份认证**。发信域名要配 SPF、DKIM、DMARC 三条记录。SPF 声明哪些服务器有权代你的域名发信；DKIM 用签名证明邮件没被篡改；DMARC 告诉收件方「认证失败时怎么处理」。缺任何一条，大型邮箱服务商都会降权。对平台来说，这意味着一套「用户接入时自动配置 DNS」的引导流程——而 DNS 是用户自己的域名，平台只能检测、不能代改，这是客服量的主要来源之一。

**第二关：IP 与域名声誉**。声誉是按 IP 和按域名累积的历史评分。新 IP 没有历史，需要「预热」——从每天几百封开始，逐步加量，让收件方建立信任。这一步没法加速，所以平台必须做**IP 池的分层**：把新用户放在预热中的 IP 上，把长期表现良好的用户放在高声誉 IP 上。

**第三关：内容与列表质量**。硬退信（地址不存在）比例高、垃圾邮件投诉率高、内容含大量图片少文本、链接指向可疑域名——这些都会触发过滤。平台必须能在发送前拦截，而不是发出去再后悔。

**第四关：退订与合规**。营销邮件必须提供一键退订，且退订要真的生效（很多平台死在「退订了还在发」）。此外还有发件人身份、物理地址等信息要求，各司法辖区规则不同。

这四关里，只有第一关是配置问题，后三关都是**持续运营**问题。这也是为什么邮件平台的技术门槛看起来低、实际很难：它不是写一个发送接口，是长期维护一个声誉系统。

## 三、设计优先，等于写一个把设计稿编译成兼容 HTML 的编译器

产品的差异化在「好看」。但邮件里的「好看」跟网页的「好看」是两套技术。

邮件客户端对 CSS 的支持极度分裂：桌面版 Outlook 用的是文字处理引擎，不支持 flex、不支持 grid、不支持负边距，很多情况下只能用表格布局；Gmail 会剥离 `<style>` 标签里的部分规则，要求关键样式内联；Apple Mail 支持得比较好，但会做暗色模式自动反色，可能把精心设计的白底邮件变成一片黑。

所以「设计优先的邮件编辑器」在技术上等于一个**编译器**：

- 用户在设计器里做的布局（拖拽、分栏、间距），要编译成嵌套表格 + 内联样式；
- 用户选的自定义字体，在没有字体支持的客户端要回退到安全字体栈，且回退后的版式不能崩；
- 图片要生成多套尺寸与替代文本，因为很多客户端默认不加载图片；
- 暗色模式下要有单独的一套配色，否则白底设计会被强制反转成难看的灰。

这个编译器的质量决定产品的口碑。用户在编辑器里看到的预览是「理想浏览器」，实际在 Outlook 里打开是另一个样子——差距越大，投诉越多。这也是这类产品最难自动测试的部分：要覆盖几十种客户端组合，只能靠截图比对。

## 四、一年 130 亿封：队列、限速与隔离

130 亿封分摊到一年，平均每秒约 400 多封，峰值会高出一个量级（比如周一上午和黑五）。

这个规模下，发送系统必须做到三件事：

1. **队列与优先级**。营销邮件不是事务性邮件，晚几分钟没关系，但不能因为一个大客户的一次群发把整个队列堵住。所以要按客户分片、按优先级排队。
2. **速率控制与背压**。往某个收件域名（比如某大型邮箱服务商）的投递速率是有隐性上限的，超了会被限流甚至封禁。必须按域名做速率控制，并根据退信/延迟信号动态调整。
3. **故障隔离**。某一个 IP 声誉掉了，要能立刻把它从池子里摘出来，而不是等所有用户投诉。这需要按 IP 维度监控退信率、投诉率、投递延迟。

这三件事共同点是：**它们都是「持续运行的系统」而不是「一次性的代码」**。零融资团队能撑住这个规模，靠的往往不是人多，而是把这套东西做得足够自动——异常自动摘 IP、自动降速、自动告警，人只在告警响了之后做判断。

## 五、零融资 + 第二周盈利，说明它卖的是「省事」

这个案例有个容易被忽略的细节：2018 年被 YC 拒绝，自筹起步，上线第二周就盈利，至今零外部融资。而同期很多邮件工具是靠融资烧增长。

差别在于它卖的东西。多数邮件平台卖的是「更多功能、更强自动化」，需要教育市场；它卖的是「**你不需要设计师也能发出好看的邮件**」，这是小企业主能立刻理解的痛点，也是能立刻付钱的痛点。

工程上这对应一个取舍：不做最全的功能，把资源压在编辑器与模板的体验上。功能少意味着维护面小，小团队能撑住；体验好意味着口碑传播，获客成本低——官方口径说他们没有销售团队，增长靠用户案例传播，这与「产品本身就是营销素材」的设计取向是自洽的。
