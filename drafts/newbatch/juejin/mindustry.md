# Mindustry 用 Java 做确定性联机：锁步同步在一个塔防游戏里怎么落地

塔防 + 物流 + RTS，Java 写的，能跑在 Windows、Linux、Android 上，还支持多人协作防守。

技术上它最值得看的是**确定性锁步同步**：多人对局里不传「谁放了什么单位」，而是传「第几 tick 发生了什么指令」，两边各自跑到同一个结果。这套机制对带宽要求极低，但对代码的确定性要求极高。

## 一、技术栈

- 语言：Java（桌面与 Android 共用一套代码）
- 渲染/输入：libGDX（底层走 OpenGL，Android 上走 Arc 兼容层）
- 网络：自研 TCP/可靠 UDP 通道（`arcnet`）
- 平台适配：桌面 JVM + Android（ART）
- 内容定义：早期在 Java 类里，v7 之后逐步迁移到 hjson 数据文件

Java + libGDX 的组合意味着：**同一份游戏代码要在键盘鼠标和触摸屏上都成立**。它的 UI 是自己画的（不用系统控件），所以能保证两端一致。

## 二、锁步同步的核心约束

多人实时策略的同步方案大致两派：

| 方案 | 传什么 | 带宽 | 确定性要求 |
| --- | --- | --- | --- |
| 状态同步 | 实体状态快照 | 高 | 低 |
| 锁步（lockstep） | 输入指令 + tick 号 | 极低 | 极高 |

Mindustry 走锁步。原因很直接：塔防场景实体数量爆炸（传送带上每格都有物品），传状态快照等于自杀。

锁步的代价是一串硬约束，每一条都要求代码纪律：

1. **所有随机必须来自同一个种子 + 同步的调用顺序**
2. **不能依赖浮点在不同平台的差异**（JVM 上 `strictfp` 或改用定点）
3. **不能有「本地时间」参与模拟**（不能用 `System.currentTimeMillis()` 算游戏逻辑）
4. **实体遍历顺序必须稳定**（哈希表的迭代顺序就是定时炸弹）

```java
// 反面示例：这在锁步里一定出问题
float damage = base * Math.random();          // 随机不同步
if (System.nanoTime() % 2 == 0) { ... }       // 时间不同步
for (Entity e : hashMap.values()) { ... }     // 顺序不同步（取决于哈希实现）
```

## 三、命令队列与 tick 对齐

客户端不直接改世界，而是把操作打包成「命令」带 tick 号发出：

```
tick 1204: 玩家A 在 (14,22) 建了 conveyor
tick 1204: 玩家B 在 (30,18) 建了 router
```

服务端（或房主）收集本 tick 所有命令，按玩家 ID 排序后广播。所有客户端在同一个 tick 应用同一批命令，结果必须一致。

工程要点：**命令必须可序列化、可排序、可重放**。这跟事件溯源是同一套思路，只是这里的事件是玩家输入。

## 四、断线重连怎么做

锁步最痛的地方：中途加入或掉线重连，客户端缺了中间几万个 tick 的历史，没法直接追上。

Mindustry 的做法是**快照 + 追赶**：把当前世界状态序列化发给新客户端，然后从快照点继续接收命令。快照的序列化成本很高（整个世界），所以只在必要时做。

这是所有锁步游戏都要面对的天花板，也是它为什么更适合作战规模有限的场景。

## 五、地图与渲染

- 地图是二维瓦片网格，每格记录地板、建筑、堆叠物品
- 渲染分层：地板 → 建筑 → 单位 → 特效，各层独立批处理
- 大量瓦片用 texture atlas 合批，减少 draw call

libGDX 的 `SpriteBatch` 在同一纹理下能合批；为了让合批生效，所有建筑贴图必须打进同一张图集。这是 2D 游戏性能的第一课：**draw call 数量由纹理切换次数决定，不是由对象数量决定**。

## 六、逻辑处理器：把脚本塞进游戏

v7 之后它内置了一个可视化「逻辑处理器」，玩家可以在游戏内拼出条件与动作，控制单位、传感器、开关。

技术上这是「沙盒内的可视化编程」：指令是一条条语句节点，运行时解释执行，且必须**在锁步环境下确定性执行**。这让脚本的运行被严格限制在 tick 内，不能做异步等待。

想给自己的产品加「用户自定义自动化」的，可以研究它怎么在确定性约束下做脚本沙箱。

## 七、读代码的入口

1. `core/src/mindustry/core/Control.java` —— 游戏主循环与 tick 推进
2. `core/src/mindustry/input/` —— 输入到命令的转换层
3. `core/src/mindustry/net/` —— 网络通道与包定义
4. `core/src/mindustry/world/` —— 方块、建筑、物流的实现

## 八、门槛

- 构建用 Gradle，Android 需要 SDK/NDK
- 代码量大，`mindustry.gen` 里大量生成代码（资源与内容生成的），直接读会迷路
- 锁步调试很难：不同步只能靠复现录像 + 二进制比对

## 九、能搬走的设计

- **实体多、状态重 → 锁步；实体少、状态轻 → 状态同步**，先算带宽再选方案
- **随机收口 + 遍历顺序稳定**，这是确定性的两条命门
- **合批由纹理决定**，图集是 2D 性能的第一优先级
- **用户脚本必须在主循环内确定性执行**，否则联机立刻崩
