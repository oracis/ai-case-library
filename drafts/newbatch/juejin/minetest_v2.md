# 我给工具加了个插件系统，第三方脚本把服务卡死了：重读 Minetest 的 Lua 边界

去年给公司内部的数据平台做插件系统。需求很朴素：业务同事想自己写取数逻辑，别每次都排我的期。

我的第一版方案只花了两天：一个 `plugins/` 目录，每个插件是一个 Python 文件，约定几个函数名（`fetch()`、`render()`），主程序启动时扫目录 import 进来，再用一条事件总线把「取数完成」「渲染前」这些时机广播出去。

上线两周，出了三件事。第一件是财务同事的插件里有个 `while True` 轮询外部接口，服务端 CPU 打满，整个平台挂了四十分钟。第二件是我自己写的官方「财务报表」模块直接 import 了引擎内部的数据库连接函数，后来想把它改成标准插件（因为业务方要求看示例代码），发现改不动——它跟内核缠在一起。第三件最尴尬：两个插件都监听 `fetch_done`，一个改了返回结构里的字段名，另一个静默失效，没人发现，直到月度报表少了一列。

三件事都指向同一个问题：我把插件当成了「能被 import 的代码」，而它其实是「一个必须被约束的第三方」。后来我去读了 Minetest 的源码——一个 C++ 的方块沙盒引擎，几乎全部游戏逻辑都由 Lua 脚本提供，包括物品、节点行为、合成表、甚至新的游戏规则。它做这件事做了十几年，边界划得比我清楚得多。

## 死循环那条，我一开始以为只能靠隔离进程

出事之后我的第一反应是把插件扔到子进程里跑，用 IPC 通信。方案写到一半就停了：取数逻辑一次要读几千行数据，序列化开销比计算本身还大。

Minetest 的选择跟我相反——**Lua 跟引擎跑在同一个进程里**。它的理由是性能：方块级的回调（挖一个方块、放一个方块、走过一个节点）触发频率极高，如果每次都跨进程，延迟和序列化成本直接吃掉整个游戏体验。

但它没有把风险扔给运气。引擎对脚本执行做了运行时保护：`core.register_globalstep` 里的 mod 代码有执行预算，超时会被记录并告警；mod 想改地图必须走引擎 API，不能直接动内存里的区块；网络包由引擎序列化，mod 只能填内容。

这里的关键区别不是「同进程还是独立进程」，而是**同进程的前提下你有没有度量**。我当时的插件跑在同一个进程里，却完全不知道每个插件用了多少 CPU——出事之前没有任何数字，出事之后只能靠 `top` 猜。

我后来的改法是给每次插件调用套一层计时，超过 200ms 记一条日志，超过 2s 直接抛异常中断。进程还在同一个，但坏插件从「能拖死全局」变成了「自己报错退出」。这比上子进程便宜太多了。

做插件系统绕不开这个选择：同进程性能好、能力全，但一个坏插件毁全局；独立进程隔离好，但序列化成本和延迟高。**Minetest 选了前者，因为它要的是方块级高频调用**。我现在会补一句：选前者可以，但必须同时把预算和度量做进去，否则那不是架构选择，是侥幸。

## 我给官方功能开了后门，这是最贵的一个错

第二件事我到现在还觉得难堪。

平台刚上线时，为了赶进度，我自己写的「财务报表」模块直接 import 了内核的数据库连接和查询构造函数——反正是自家代码，何必绕一圈走插件 API。

半年后业务方说：能不能把官方模块的源码给我们看看，当写插件的范例？我打开文件才发现，它用的那些内部函数，插件 API 里一个都没暴露。要让它变成「标准插件」，等于把整个 API 层补齐再重写一遍这个模块。

Minetest 在这件事上的处理，是我读源码时最意外的一处：**默认游戏 Minetest Game 本身就是一堆 Lua mod，跟第三方 mod 的地位完全一样**。官方玩法不享受引擎特权，走的是同一套 `register_node`、同一套回调、同一套沙箱限制。

这个设计的价值不在于「公平」，而在于**它会持续打磨 API**。如果官方玩法有一条私有通道，那 API 上所有别扭的地方都可以绕过——绕过去的人永远不会喊疼，接口就永远长不大。我那个后门就是这样：官方模块绕过了插件 API，所以我从来没发现 API 缺了什么，直到第三方真的要用。

这条结论我现在的说法是：**官方功能必须吃自己的狗粮，而且要用最难的那条路径吃**。

## 靠字段名约定，比靠父类还脆

第三件事，两个插件互相踩字段。

我第一版的事件总线是这样用的：插件监听 `fetch_done`，收到的参数是个 dict，约定里面有 `rows`、`columns`、`source`。约定写在 README 里。一个插件把 `columns` 改成了 `headers`（它觉得更贴切），另一个插件静默失效。

Minetest 用的是注册表，不是继承，也不是事件总线：

```lua
core.register_node("mymod:stone_brick", {
    description = "Stone Brick",
    tiles = {"mymod_stone_brick.png"},
    groups = {cracky = 3, stone = 1},
    on_dig = function(pos, node, digger)
        core.remove_node(pos)
    end,
    on_rightclick = function(pos, node, clicker)
        core.chat_send_player(clicker:get_player_name(), "clicked")
    end,
})
```

三个点值得对照着看。

一是**注册表而非继承**。引擎维护一张 `name -> definition` 的表，行为通过字段挂上去，不要求写类。接入门槛低，而且引擎永远知道有哪些对象存在——这一点比继承强：继承体系里你无法枚举「所有可能被注册的东西」。

二是**回调挂在对象上，而不是全局广播**。每个节点自己带 `on_dig`、`on_rightclick`。我的事件总线是全局的，所以「谁在监听」永远是运行时才知道的事；它的回调是数据的一部分，注册那一刻就确定了。

三是**字段名是 API 的一部分，由引擎定义，不由插件商量**。我那套约定失败的根本原因，是字段名处在一个「大家都以为知道」的灰色地带。

我现在把插件接口定义成显式的结构体（Python 用 dataclass），并且版本号写进字段。改字段就是改版本，老插件在新版本上跑不起来会立刻报错——比静默失效好一万倍。

## 按类型判断，我第二次踩了同一个坑

修完字段问题，我加了权限控制：不同插件能访问的数据表不一样。我写的是 `if plugin.type == "finance" or plugin.type == "audit"`——按类型判断。

加第三个类型的时候，这个条件变成了四行，并且漏了一处。

Minetest 的 `groups = {cracky = 3, stone = 1}` 是另一套思路：不给方块定类型，而是给能力分组。`cracky = 3` 的意思是「可被镐类工具挖，硬度 3」，工具只需要判断分组，完全不需要知道具体是什么方块。加一种新石头，不用改任何工具代码。

这是**面向能力而不是面向类型**的设计。我在自己的权限系统里改成「给每张表打标签，插件声明需要哪些标签」，条件从「是什么」变成了「要什么」，扩展点自然就长出来了。

## 我没搬的部分

Minetest 的区块是 16×16×16 的 `MapBlock`。选 16 的理由很讲究：16³ = 4096 个节点，按每节点 2 字节算约 8KB，压缩后很小；块内坐标正好是 4 bit，用位运算就能算偏移；渲染、网络同步、磁盘存储、内存缓存全都以块为单位，粒度统一。

但我不做体素系统，这条对我没用。它背后那句结论我倒是抄走了：**网格类系统要让「渲染粒度 = 存储粒度 = 同步粒度」**。三个粒度一旦不一致，就会出现「改一个字段要重传一整片」「存档要跨块拼接」这类连锁麻烦。我做报表缓存的时候正好踩过——按行缓存、按页渲染、按天同步，三层粒度互相对不上，最后改成全部按「数据日期」切分才干净。

它的网络协议我也没抄。Minetest 是二进制、按块增量同步，玩家进视野下发整块、块内变更只发坐标和内容、块有序列化版本号。实时沙盒必须这样，玩家每挖一个方块发一次 JSON，带宽立刻爆。我的场景是每天一次批量取数，JSON 完全够用。

编译门槛那部分我也只当参考：它依赖 Irrlicht、SQLite 或 LevelDB、LuaJIT、zlib、OpenAL，Windows 下配 CMake + vcpkg 大概要一个下午，Lua API 文档散在 `doc/lua_api.md` 且版本间有破坏性变更。这些是它的历史包袱，不是设计智慧。

## 真正搬走的是三条

一是**官方玩法也走插件通道**。这条最反直觉，也最值钱：它保证 API 不会因为内部需求被扭曲。

二是**同进程可以，但必须有预算和度量**。隔离级别不是靠进程边界买来的，是靠「每个插件用了多少资源我随时知道」买来的。

三是**按能力分组，不按类型分支**。类型会膨胀，能力相对稳定。

Minetest 现在叫 Luanti，源码在 `minetest/minetest`，许可证 LGPL 2.1+，以仓库为准。想读代码的话，入口是 `src/mapblock.cpp`（块序列化）、`src/script/lua_api/`（Lua 绑定怎么落到 C++）、`builtin/game/`（用 Lua 写的默认游戏逻辑），以及 `games/minetest_game/mods/`——最后这个就是「官方玩法如何把自己写成插件」的活样本。
